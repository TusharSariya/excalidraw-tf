## Findings

### **[P1] “Parity” is configuration-specific; default Strata remains materially worse than v2**

All three optimizations used for the W4 parity claim are default-off: K=0, A7 off, rankSeparate off ([`useTerraformImportDialog.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/useTerraformImportDialog.ts:121), [`terraformPipelineStrata.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/terraformPipelineStrata.ts:93)). Selecting Strata does not yield the validated W4 arm.

| Preset | Honest current delta against v2 |
|---|---|
| **P1 compact** | Default K0: crossings 273 vs 177; median deviation 1093 vs 402; slice-B p90 17,723 vs 7,098; height 19,066 vs 10,056. Fully optimized W4 arm: paired mean −112px, CI `[−956,+784]`; p90 still 9,166 vs 7,098; height still 13,761 vs 10,056. This is parity on one mean-CI statistic, not overall readability parity. |
| **P2 compact** | Default K0: crossings 39 vs 33; median 1,523 vs 459; slice-B p90 10,135 vs 1,955; height 12,106 vs 5,734. K4+A7 remains worse: median 1,439, p90 7,487. W4 rankSeparate remains v2-favoured, CI `[+1178,+3142]`. |
| **P3 multistate** | W3 states Strata matches P2’s numbers; this composition resolves to the same effective graph for the relevant arms. No W4 rankSeparate cell exists. It is not independent validation. |
| **Cyclic** | K4+A7 improves crossings, 124 vs 175, with R2 zeros. No W4 extent, default-arm, or impact-tracing result was reported. This establishes structural robustness, not readability superiority. |

P1 full mode shows a large optimized extent win, but that comparison is explicitly voided by slice-classification/ancillary asymmetry. Evidence: [W3 §§1–4](/Users/tusharsariya/Projects/excalidraw-tf/docs/strata-view-w3-battery-report.md:20), [W4 §2](/Users/tusharsariya/Projects/excalidraw-tf/docs/strata-view-w4-extent-report.md:42).

### **[P1] The “strict §2.5 pass” being chased is not the specified p90 gate**

The normative metric family gates slice-B p50 and p90 (`rcll-v2-spec-v3.md` §2; v3.1 §2.5/§12). The implementation instead bootstraps the **mean paired delta** ([`terraformPipelineBootstrapCi.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/terraformPipelineBootstrapCi.ts:121)). `bootstrapGatePolicy` labels a cell “p90,” but the result is not used to bootstrap or decide p90. The harness declares a pass solely when the mean CI has `hi < 0`, and explicitly never asserts it ([`terraformPipelineStrataExtentGate.test.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/terraformPipelineStrataExtentGate.test.ts:422)).

W4 is the counterexample: the arm is called statistical parity because mean CI straddles zero while p90 is still **+2,068px worse**. OD-15 could therefore obtain a “strict pass” while the named tail statistic—and potentially impact tracing—remains worse. Chasing that result is not legitimate roadmap evidence until the gate contract and harness agree.

### **[P1] The primary task has never been evaluated—and its direction prerequisite was skipped**

SDEC-9 defines the task as impact tracing, but §2.5 measures geometry proxies. The scheduled Q7-AXIS check—whether the X direction actually matches the dataflow direction users follow—has no result artifact: a reproducible `rg Q7-AXIS docs packages/excalidraw/components` finds only plans in v3.0 §8.5, SDEC-24, and the implementation flow.

The owner checkpoints were visual N=1 reviews, not path-tracing trials. SDEC-47’s acceptance was effectively “looks good / trust the implementation,” despite the failed automatic gate.

This distinction matters empirically:

- Ware et al. found shortest-path performance primarily affected by path length, continuity, crossings, and branches—not canvas height alone ([paper](https://vislab-ccom.unh.edu/pdfs/GraphAesthetics.pdf), corpus `doi-10-1057-palgrave-ivs-9500013`).
- Huang’s 16-person path-search study found crossing angles and misleading geometric path tendency affected tracing performance ([paper](https://arxiv.org/abs/0810.4431), corpus `forward-10-48550-arxiv-0810-4431`).
- The empirical-evaluation survey says feasibility ultimately requires human performance on relevant graph tasks ([paper](https://eprints.gla.ac.uk/227646/1/227646.pdf), corpus `s2-10-1109-access-2020-3047616`).

The missing comparator is also frame-level: not just static Strata vs static v2, but **Strata vs v2 with selection-driven upstream/downstream highlighting**. A 32-participant study found combined static and temporal subgraph highlighting at least as effective as static highlighting for path tracing ([Ephemeral Paths](https://www.cs.ubc.ca/tr/2011/tr-2011-10)). That interaction may buy more impact-tracing performance than another layout pass and would benefit the shipped default.

A task-grounded crossover should measure accuracy, completion time, wrong-branch/backtracking count, pan/zoom distance, and confidence for:

1. direct and transitive dependents;
2. direct and transitive dependencies;
3. path existence between two resources;
4. first boundary crossed across module/account/provider;
5. changed-resource impact after a plan diff.

Conditions should include v2, v2+trace highlighting, default Strata, and optimized Strata, on held-out real states.

### **[P1] The evidence base cannot support a direction decision**

Round 6 itself says “two distinct graphs, still not a battery.” P3 is composition consistency over P2’s effective graph; cyclic is one injected reverse edge; W4 evaluates only P1/P2; the battery remains AWS-taxonomy-specific; and no real all-resources readability or task trial exists. Seed `20260704` makes bootstrap results reproducible—it does nothing for stimulus representativeness.

Required coverage is missing for multiple providers, non-AWS providers, deep module nesting, high fan-out, dense and sparse states, ancillary-heavy states, and several naturally cyclic graphs. Owner validation does not replace that sample.

### **[P1] S7/M3 is materially less specified than the layout engine**

The export re-stack seam is closed for M1: Strata bypasses `applyCompoundHierarchicalLayout` and has a multi-provider provider-Y assertion (`implementation-flow` P8; SDEC-34). Do not re-litigate it. The risk returns only because the ancillary port has no comparable scene-build contract.

The actual integration gaps are:

- Generation remains constant at `1`; the app-side monotone counter is explicitly deferred to S7/M3 ([`terraformPipelineStrata.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/terraformPipelineStrata.ts:43)). Until implemented, same-cardinality regeneration/collab propagation re-enters the exact failure class found in round 5.
- `TerraformOverlayStore` is “app-level, keyed by address” but specifies no scene/import/workspace namespace, storage lifecycle, conflict policy, undo/redo behavior, or migration rules (`rcll-v2-spec-v3.1.md` §6.2).
- Full mode can create multiple satellite appearances for one address (SDEC-42), while styles/group members remain keyed by bare address. Whether edits apply globally or to one appearance is undefined.
- “Pre-Strata scenes re-import” is not a saved-scene migration contract.
- `replaceAllElements` mechanics specify post-apply styles/annotations, but not capture-before-replace, persistence failures, collab merge ordering, or behaviour during degraded-v2 fallback.
- Preset selection bypasses `handleSetView` and calls raw `setView` ([`useTerraformImportDialog.ts`](/Users/tusharsariya/Projects/excalidraw-tf/packages/excalidraw/components/useTerraformImportDialog.ts:760)); per-view option and overlay switching semantics remain incomplete.

S7 is therefore not implementation-ready.

### **[P1] OD-15 is gate-worship and the wrong opportunity-cost choice**

W4 already records that the residual is driven by full-width provider/account bands, while OD-15 removes subnet-level frames; its payoff is explicitly uncertain and visually changes containment frames into rails (`strata-view-w4-extent-report.md` §4). There is no evidence that this improves impact tracing, and removing hierarchy cues could hurt it.

Meanwhile Strata is the fourth pipeline engine (`rcll-v2-spec-v3.1.md` §7, Q5-TCO), and the engine-endgame decision has not occurred. The same effort spent on view-agnostic dependency selection/highlighting would directly address the primary task and improve the shipped v2 baseline.

### **[P2] Fix the icon-ownership flake before overlays depend on canonical identities**

The finalize flake is rare and probably test-environment-sensitive, but its mechanism is unconfirmed and relies on geometric containment to assign icon ownership (SDEC-52; W4 §3). Failure degrades to v2 output, disabling Strata-scoped tombstones and canonical identity assumptions. It is not direction-threatening alone, but it must precede S7/collab work.

## Verdict

**NO-GO** on proceeding as planned. Strata should remain available as an experimental engine, but the roadmap has not established that it beats the default for impact tracing. “Parity” applies only to an opt-in configuration and one mean-CI statistic; P2 remains materially worse, P3 is non-independent, cyclic evidence is structural only, and the gate implementation does not enforce its named p90 objective. Stop OD-15 and S7 investment until a task-level comparison—including v2 with tracing interaction—shows where Strata creates user value.

## What I would change

1. **Insert a task-evidence milestone now.** Run Q7-AXIS plus randomized impact-tracing trials on representative real states, comparing v2, v2+trace interaction, default Strata, and optimized Strata.
