## 0. TL;DR

Readability is the objective — but the crossing/deviation metric family is miscalibrated against the owner's own revealed preferences (§4.3). ### CRITICAL

**F1 — A3's pseudocode is wrong: the double-reverse mass-misclassifies feedback arcs.** *(5 independent sources + mechanical trace)*
§10-A3 prepends sinks to `rightSeq` **and then** computes `s = leftSeq ++ reverse(rightSeq)`. Canonical GreedyFAS (ELS93, verified against the verbatim restatement in Geladaris/Lionakis/Tollis JGAA 27(8) 2023 Algorithm 1: `s2 ← u·s2 … return s = s1 s2` — **no reverse**) prepends *or* reverses, never both. Trace `a→b→c`: sinks removed c,b,a → `rightSeq=[a,b,c]` → reversed `[c,b,a]` → **every edge of an acyclic chain is classified feedback**, reversed, and styled backward — destroying the exact L→R reading the owner wants. Worked cyclic counterexample (2-cycle + 3-chain): spec yields |F|=3 vs correct 1. **T7 as specified does not catch this** — a minimal 2-cycle fixture makes the reverse a no-op. Compounding defects: self-loops never enter F (`index(u)>index(u)` is false) so "the graph is now acyclic" is untrue and A1's determinism clamp re-fires *in the new engine*; no SCC condensation; §5.4 "leaf cycle" vs S9 "collapsed leaf TFD" vs A1 "collapsed edges" input ambiguity (module collapse is what *creates* the 2-cycles/self-loops); the spec never states post-A3 phases consume `E′=(E−F)∪reverse(F)` — as written, A2's barycenter ignores reversed arcs, unlike graphviz/dagre/ELK which treat them as forward until draw; and whole-graph greedy FAS is deterministic but **not diff-stable** (an unrelated edge can flip *which* arc of an untouched cycle gets styled backward — R7 analyzed for A2, never for A3). Of these, the double-reverse, self-loop, and E′ defects are correctness blockers; SCC condensation + model-order arc selection are quality/diff-stability improvements (whole-graph GreedyFAS is otherwise valid), recommended rather than blocking.
**Fix:** `s = leftSeq ++ rightSeq`; input = collapsed graph; drop self-loops (adornments); Tarjan-condense, GR per nontrivial SCC with model-order-consistent arc selection; add the E′ contract; T7 must use a cycle+chain fixture, assert |F|=1, pin the reversed arc, and assert F=∅ on an acyclic fixture.

**F2 — A2 is REFUTED as written — not by the citation alone, but because its own stability proof is false and it can breach R2.** *(3 independent paper fetches + codex + eng review; the citation defect alone would be "readability risk", the proof/contiguity defects make it unsound against the spec's own objectives)*
Domrös & von Hanxleden GD'24 (arXiv:2406.11393) recommends **Strategy 1** — keep crossing-minimization layer sweeps primary, use model order as the *secondary/stable tiebreak* — and explicitly documents that **Strategy 2** (model order only, no sweeps — which is what A2 is) *"cannot be the default option, since it produces ONO [Obviously Non-Optimal] layouts"* and *"may increase the edge crossings significantly."* The architecture doc even records the correct Strategy-1 reading ("Strategy 1 keeps crossing-min primary… grounds D1") — the spec then implements Strategy 2 and defers the sweep to §8. Four further defects, each independently disqualifying as written:
- **The stability proof is false.** `key(c)` uses the numeric **mean of predecessor ordinals**; ordinals depend on the entire upstream column membership, so adding one unrelated source shifts `ordinal(p)` and re-keys untouched `c` — the claim "editing an edge that does not touch c or c's predecessors cannot change key(c)" conflates key-stability with ordinal-stability. (The foundation spec's D1 was the sorted address **tuple** — the numeric-mean drift in the final spec broke its own invariant.)
- **No hull-tree constraint.** A2 orders a column globally; nothing prevents interleaving members of sibling hulls (`A1,B1,A2,B2`). Hull frames are subtree bboxes, so interleaving = non-ancestor frame overlap = **R2 breach** (structural, not just R4 aesthetics) — or the placement silently overrides the computed order, making the fed-forward ordinals and T2's flip metric fictions. The compound-ordering literature (Forster 2002, Sander 1996) exists precisely for this and is uncited in A2.
- **Cross-column ordinal mixing is unsound.** Predecessors at `depth(p) < d−1` contribute raw ordinals from non-adjacent, differently-sized columns (ordinal 3 of 4 ≠ ordinal 3 of 40); classic Sugiyama uses adjacent-layer positions via dummy chains — which the spec has removed without disposition (v1's DEC-5 raised them; the spec is silent).
- **Sources are ordered alphabetically** (`SOURCE_BUCKET`, address sort) — the leftmost, everything-anchoring columns are visually arbitrary, and no downward pass can ever repair a bad source order (sources have no predecessors; only the successor sweep the spec deferred could).
**Fix:** hull-scoped recursive ordering; deterministic fixed-iteration barycenter sweeps (up+down) with the content key as tiebreak — Strategy 1 exactly; stateless and R7-compatible (path-*dependence* is what breaks R7, sweeps do not); measure the stability cost with T2 instead of assuming it.

**F3 — A4/T2, the M1 exit gate, cannot gate anything.** *(literature agent + codex + eng review + refute panel CONFIRMED + empirics)*
(a) **The citation is inverted**: Sondag/Speckmann/Verbeek 2018's relative-position-change is a pairwise 8-sector *directional* measure in [0,1]; the paper's own words: absolute-position measures are *"not sufficient to measure the stability"* (their Fig. 19: a perfectly trackable layout scores distance-change 5.325, relative-position-change 0). The spec cites the paper **for the measure the paper was written to replace** (median/p95 `|Δpos|`). (b) `ordinalFlips = #{a,b : sign(ord_old) ≠ sign(ord_new)}` is malformed — as written it is **identically zero** (ordinals are non-negative; the pairwise form `sign(ordΔ_old(a,b)) ≠ sign(ordΔ_new(a,b))` was meant), so the gate's only relative-order term is vacuous. (c) **No thresholds are specified anywhere** — "PASS iff < thresholds" with unset thresholds is unfalsifiable; the same defect infects S8 ("not-regress vs own baseline", never frozen — a bad first baseline passes itself) and T8. (d) `U` requires S7's content hash — **which is M2+ work**; the M1 gate cannot compute its own allowlist. (e) Raw `|Δpos|` is a **false-fail generator** under the spec's own model: `columnX` derives from per-column max card width, so one wider label (or any added column-member) legitimately translates whole columns — empirically confirmed (§5.1: benign global shifts dominate Δ). The metric must be translation-invariant / rank-scoped.
**Fix:** implement the actual Sondag pairwise-directional measure (or an honest rank/inversion metric) + within-column order flips; define an interim structural hash inside S2 (address + incident endpoints + parent + collapse classification), superseded by S7; run the fixture triple once, then freeze thresholds by spec amendment.

**F4 — Readability is not deferred, it is unscheduled — and the milestones improve none of the measured baselines.** *(all voices + Q2 empirics)*
Coordinate assignment/straightening (Brandes–Köpf), crossing-min sweeps, dummy-node long-edge handling, and edge routing appear **nowhere** in R1–R10, S0–S10, or §8's deferral list with a scheduled return. Measured reality (§4): v2 baseline 177 crossings / 402px median vertical deviation / 17% near-straight / 5% hub centering; the owner's own view 371 / 701 / **10%** / 11%. M1+M2 as specified move **none** of these numbers. The one metric no existing lever can move — `fractionNearStraight`, pinned 0.10–0.17 across **all seven arms** measured — is precisely the one that needs the coordinate-assignment phase the spec never schedules. A layered layout with one forward ordering pass, no sweeps, no dummy nodes, and no coordinate assignment is the literature's known-bad configuration (Handbook ch. 13; the GD'24 "ONO" result; v1 RFC §23.1's own evidence ranking). D3's fork also **discards v1's built passes** (crossingMin/straighten/coordRepack/columnCompact/NS-shorten) without replacement — the new engine is the *least* readable of the three on day one.
**Fix:** §6 below — readability payload moves into the first engine milestone; diff-stability becomes its frozen not-regress gate.

**F5 — A6's fixed `version=1`/`versionNonce=0` breaks propagation; four more identity defects.** *(A6 agent + P1 verification + codex + refute panel)*
With deterministic ids and constant version/nonce, a regenerated element is bit-indistinguishable from the one it replaces: collab reconcile keeps the stale local copy (`reconcile.ts:35-39`), and — for **same-cardinality regenerations** (pure geometry/reorder changes; adds/removals do bump the sum-of-versions scene version) — the broadcast and Firebase save gates never fire, so **geometry-only regenerations silently neither propagate nor persist in collab**, and a peer holding the pre-regenerate scene resurrects removed elements (the regenerate path never bumps versions — `applyTerraformExcalidrawScene` passes `existingElements=null`, `bumpElementVersions` is never called). Additional confirmed defects: (a) `edgeId` endpoint-sorting collides `A→B` with `B→A` — the exact pair S9's reversal styling produces — and parallel relationships; `"__"` is not prefix-free over legal Terraform identifiers; "content-derived ordinal" is named, not specified. (b) `hashToSeed` can emit 0, and **RoughJS treats seed 0 as unseeded** (`if (this.seed)` truthiness, `math.js:8-14`; `ops.seed || 0` → `Math.random()` per render) — R6 broken at render time (repo's own `randomInteger` can also emit 0, a latent pre-existing bug). (c) Frame-like element ids are emitted **unsanitized** into SVG exports (`clipPath id` at `scene/export.ts:404`, `url(#${frame.id})` at `staticSvgScene.ts:79`, masks at `:287/:330/:534-585`) — quotes/spaces in a `tf:frame:<address>` id (legal in `for_each` keys) silently break clipping/masking (the CSS `url()` token, not the XML). Plain-node ids are safe (never emitted). (d) `restoreElements` silently **randomizes duplicate ids** (`restore.ts:739-741`) and silently drops throwing elements — the identity contract must prove uniqueness *before* restore or determinism dies invisibly. (e) The id-rewrite plan (S3) overlaps machinery that already exists: `convertToExcalidrawElements` only remaps arrow endpoints + frame children; everything else is repaired post-hoc by `repairTerraformEdgeBindings` via customData (`terraformVisibility.ts:969`) — integrate or replace, don't duplicate.
**Fix:** content-hash-derived `version` (or bump-on-regenerate), nonzero-clamped seeds, direction-preserving + length-prefixed edge ids, SVG-safe frame-id sanitization, a pre-restore uniqueness assertion, and an explicit S3 disposition for the existing repair pass.

**F6 — S7/C9 is designed around a code path regenerate never takes; the real hazard is the opposite one.** *(P1 verification + eng review live re-check + trace)*
The actual regenerate path is `refreshTerraformLayout` (`terraformSceneApply.ts:439`) → `runTerraformImportFromSources` (`:318`) → `applyTerraformExcalidrawScene` (`:71`) → **`scene.replaceAllElements` (`:124`)**. `reconcileElements` is **never called** (it is collab-transport-only), so the C9 "re-append at `reconcile.ts:103-107` → double representation" hazard does not exist on the real path. What does exist is the inverse: **wholesale replacement destroys every user edit** — annotations, styles, groupings, positions — which is precisely the value R9 exists to protect, and it means Round 4's "editable seed" premise is currently unshipped (there are no surviving edits and no overlay users). S7's "replace-by-canonical-id **or** bypass reconcile" is also an unresolved either/or with different deletion semantics, not a contract.
**Fix:** a regenerate-path decision spike **before** S7 design; redesign S7 around `replaceAllElements` (overlay re-application post-replace), keep the reconcile analysis only for the collab lane (where F5 applies).

**F8 — C6's seam inventory is undercounted: four-plus silent-drop modes, two of which fail invisibly.** Beyond the two sites the spec names: (c) `terraformSceneApply.ts` session-mapper + spread literals (~`:284/:370`) + the `LayoutSceneContext` type; (d) the **`skipLayoutCache` allowlist (`terraformSceneApply.ts:253-261`)** — verified live: an un-allowlisted `rcll-v2` preset import **silently serves stale KV-cached geometry from the old engine** (everything renders; it's the wrong engine's output). **F9 — A1 hard-codes the literature's low-quality layering and forbids the repo's own better kernel.** Longest-path layering "performs very poorly in terms of drawing area, number of dummy vertices and edge density" (Healy–Nikolov, Handbook ch. 13 p. 421) — the pathologies are exactly the owner's complaint class (long edges, spread). The repo contains an **exact, pure, deterministic network-simplex kernel** (`computeNetworkSimplexDepths`, `Shared.ts:638`, measured −8.4% width, in-code "the proven width win") that starts from the longest-path floor and preserves strict forwardness — `X = columnX[NS-rank]` satisfies R1/R3/C1/R6 identically. The spec never mentions it — not in §5.1, §8, or §11-rejected — and C1 as written names longest-path only. Also: §5.1's "depth changes are localized" claim is false as stated (depth cascades transitively; `columnX` widths shift globally — empirically the dominant Δ term), and the reused `computeDepths` interface **requires `sequence` in its edge type**, contradicting C4's "edge.sequence does not exist in the new path" (the cyclic clamp consuming it is also worse than the spec says: a cycle's clamp value is a raw TFD sequence number — depth 500 in a 10-column graph — blowing out the column array; both NS/ALAP rewrite arms skip silently on `hasCycle`). **Fix:** amend A1/C1 to permit NS-refined ranks via the S4 pure gate, A/B the R7 cost with T2; fork a sequence-free `computeDepths` signature; A3-before-A1 ordering is mandatory (F1).

**F10 — A5 measures a fiction against a miscited grounding, with an unfalsifiable gate.** Every emitted edge today is a single straight 2-point chord (center-clipped, orbit-bound — verified in three emitters); "routed segment" has no referent, and bindings can move endpoints after layout freezes numbers. Ware/Huang/Kobourov studied container-free stimuli — none supports container-pierce as *their* quantity (the architecture doc itself admits N1 "did not excuse" it; A5's grounding line attributes it anyway — container-pierce is defensible, but as a faithfulness/false-membership argument, not by those citations). `segmentsCross` decides proper crossings only — collinear/tangent/containment/boundary cases are undefined for rect-piercing (six ambiguous cases enumerated). "Not-regress vs the engine's own baseline" with exactly one candidate and no frozen baseline is a tripwire, not a gate — and R4's second quantity, **cluster non-contiguity, has no metric, step, or test anywhere**. **Fix:** rename to chord-pierce; define boundary semantics; freeze the baseline at M1-exit; add the contiguity metric (it is also the missing A2 constraint's test).

**F11 — Round 4's priority inversion was built on over-read citations — but the correction is calibration, not reversal.** Refute-panel-verified: Kobourov GD'14 found crossings **significant at 40 vertices** (time p<.01, accuracy p<.05) and n.s. only in aggregate at 120 (where large-*dense* accuracy was still significantly hurt; the "<39% accuracy" often quoted belongs to a 150-vertex/density-3.5 preliminary; stimuli were undirected force-directed/MDS, not layered) — citing it to demote crossings at Terraform per-container scale inverts its finding. Ware 2002 keeps crossings top-2 for path tracing. Meanwhile the inversion's own #1 (mental-map preservation) is the corpus's most-replicated **null**. And "regenerate-per-PR + editable-seed" entails *identity*-stability (anchors, ids, diff status), which is geometry-independent — not geometry-stability-above-readability. **However** (the calibration): the owner's revealed preference (§4.3) — preferring the arm with the *most* crossings because it wins deviation/height/containment — shows crossing *count* is genuinely not his dominant criterion either; path-straightness/deviation and containment legibility are. Both Round 4 ("crossings don't matter → defer everything") and a naive reversal ("minimize crossings first") would optimize the wrong number. The metrics that track the owner's eye: vertical deviation, near-straightness, hub centering, aspect, pierce/contiguity.

**F12 — S0 hides the largest unknown in the plan: the compound placement algorithm does not exist.** No pseudocode for hull construction, frame extents, title geometry, band policies, or how depth-pinned leaves produce multi-column containers — "forked ordering/placement loop" is a label. `dropY` is a private, local, monotone-downward drop primitive (never fills gaps between placed rects, `V2Pack.ts:150`), not an R2 proof — R2 (title bars, nested frames, non-ancestor separation) is carried today by structure the spec doesn't restate. ### 4.2 What the data settles
